### 0.5 竞品短板
1. 两套模式分开维护，需手动「同步 / 回传」，并非真正一份数据
2. 预览区拥挤：金额列、TOTAL 被截断
3. 右侧表单过窄，内容被截断（UNITED STA、LOS ANGELE）
4. 有「下一步」但没有整体进度、不知道还缺什么

8. 名称混乱（标签叫「报价单」，标题是 PROFORMA INVOICE），单据标签重叠

### 1.2 规则
- **一个订单 = 一个独立档案**：客户、货代、报关行、产品、条款、全部单据都存在订单里，订单之间互不影响
- 订单号按规则自动生成（如 2026-001，可自定义前缀），另可起名 / 备注
- 订单内各单据编号由订单号派生（PI-2026-001、CI-2026-001……），可改
- 同一订单内各模块数据打通：合同里填过的，发票、箱单、报关自动带出
- **复制订单**：老客户返单，复制旧单改数量即可
- 订单状态：询价 → 报价 → 确认 → 生产 → 出货 → 收款 → 完结

### 1.3 资料库（独立于订单，供订单调用）
| 库 | 内容 |
|---|---|
| **客户库** | 公司名称、地址、税号/VAT；多个联系人（姓名、职位、邮箱、电话/WhatsApp）；多个收货地址 / 收货人 / 通知方；**默认交易习惯**（贸易术语、付款方式、币种、目的港、唛头、单据语言、客户指定格式）；客户来源、等级、备注；**历史订单与累计金额**（自动统计）；跟进记录 |
| **合作方库** | 货代、报关行、工厂 / 供应商、船公司、保险公司：名称、联系人、地址、银行信息、常用资料 |
| 产品库 | 见第 0 节 |
| 条款库 | 常用付款、交货、质量、不可抗力等条款 |
| HS 记忆库 | 品名 ↔ HS 编码 ↔ 申报要素 |

### 1.4 订单与资料库的关系
- 新建订单 → 从客户库选客户 → 客户信息 **+ 默认交易习惯**一起带入（贸易术语、付款方式、港口、唛头全部预填）
- 询单时客户库里没有 → 在订单里直接填，一键「保存到客户库」
- **带入的是快照**：之后修改客户库，不会改动已做好、已发出的旧订单单据；需要时可在订单里点「从客户库刷新」
- 订单里改了客户信息 → 提示「是否同步更新客户库」
- 客户详情页可看到该客户的全部历史订单，点击直接打开

## 4. 关键技术问题

### 4.1 AI 接入：用户自带 API Key（BYOK）
- 设置页填入自己的 AI 服务和 Key：Claude / OpenAI / DeepSeek / 通义千问 / Kimi，或任何 OpenAI 兼容接口
- 软件从用户电脑直接调用，数据只发给用户自己选的服务，我们不经手
- **不填 Key：AI 按钮置灰，其它全部功能离线正常使用**
- 后期可选：我们提供「AI 点数包」，给不想折腾 Key 的用户（额外收入）

### 4.2 AI 识别 PO：不达标不上线
- **Excel / CSV 格式的 PO：不用 AI**，列映射导入（记住每个客户的格式），离线、100% 准确，M1 就做
- PDF / 图片 PO：AI 识别 → 结构化数据 → **左原件右结果的核对界面**，低置信度字段标黄，型号自动匹配产品库
- 上线门槛：用 30–50 份真实 PO 做测试集，字段准确率达标（如 ≥95%）才放出；手写、模糊扫描件明确提示不支持

### 4.3 提单核对
- 文字版 PDF（货代发的多数是）：本地提取文字 + 规则匹配字段，**离线可用**
- 扫描件 / 图片：需 AI 识别（有 Key 时）
- 兜底：直接粘贴提单文字
- 核对项：发货人、收货人、通知人、货描、唛头、件数、毛重、体积、港口、柜号封号；与订单对比，差异标红

### 4.4 信用证审证：规则库 + AI 知识库
| 层 | 联网 | 能做什么 |
|---|---|---|
| 规则层 | 离线 | 解析 MT700 标准字段（31D 效期、44C 最迟装期、48 交单期、39A 溢短装、43P/43T 分批转运、46A 单据、47A 附加条款）；日期冲突、金额容差检查；**内置软条款特征库**（如「检验证书由申请人签发」「经申请人确认后生效」等常见陷阱）逐条匹配 |
| **与订单比对** | 离线 | 信用证 vs 我方订单：金额、货描、港口、交期、贸易术语是否一致——这是单独把 L/C 丢给 AI 做不到的 |
| AI 层 | 联网（BYOK） | 软件**内置知识库**（UCP600、ISBP745 要点、软条款案例库、审证清单），连同信用证原文一起交给 AI 判断 → 输出：风险条款原文 / 风险原因 / 改证建议措辞 |

与目前「把信用证丢给 AI」的做法相同，但知识库、比对订单、结构化报告都内置，且离线时规则层照常工作。

### 4.5 HS 助手（本地）
- 内置本地数据库：中国海关税则 10 位编码、商品名称、申报要素模板、监管条件、出口退税率
- 税则每年 1 月调整、退税率不定期调整 → 通过**软件更新包**更新数据（联网自动 / 离线导入更新文件）
- 叠加用户自己的 HS 记忆库（录过的品名自动复用）
- 待办：确认数据来源与使用授权

### 4.6 多语言单据（离线方案）
| 内容 | 做法 | 离线 |
|---|---|---|
| 单据固定文字（标题、表头、字段名、标准条款）——占单据大部分 | **我们预先人工翻译好**内置到软件，准确 | ✅ |
| 品名、描述 | 产品库存多语言名称，录一次反复用 | ✅ |
| 其他自由文本（地址、备注） | 一般保持英文；有 AI Key 时可一键翻译 | 可选 |

不做离线机器翻译模型（体积大、外贸术语翻译质量差）。

### 4.7 激活授权：离线签名激活码
- 用户软件生成机器码 → 我们用私钥签发激活码 → 软件内置公钥校验
- **无需服务器、无需联网**，与竞品「一机一码」一致
- 激活码可带版本和到期日（永久版 / 年费版）

### 4.8 云同步与订阅：怎么落地（后期可选）
架构是**本地优先**：数据主存用户电脑，云只做备份和多设备同步，断网照常用。分三步，按需推进：

| 步骤 | 做法 | 需要服务器 |
|---|---|---|
| ① 文件夹同步 | 数据文件放在坚果云 / OneDrive / 百度网盘同步文件夹，自动多设备同步和备份 | ❌ 零成本 |
| ② 年费版 | 激活码带到期日（见 4.7）：年费含更新、HS 数据更新、AI 点数；到期后软件仍可用，只是不再更新 | ❌ |
| ③ 真正云端版 | 云服务器提供：账号登录、数据同步、文件存储、订阅校验；多人协作、手机查看 | ✅ 云服务器约 ¥100–300/月起、需 ICP 备案、在线支付需企业资质、数据安全责任 |

建议：①② 足以支撑早期售卖；③ 等销量验证后再决定。

| 整体结构 | 首页订单列表 → 订单菜单 → 功能模块；每个订单数据独立；客户库、合作方库独立，订单调用时带入快照 |
| 币种 | 放在货物明细最上方，按订单统一（一张单据一种币种）；默认取客户习惯；支持 USD/EUR/GBP/CNY/JPY/AUD/CAD/HKD/AED |
| 付款方式 | 12 种 + 自定义；按方式出现定金比例、尾款节点、天数等参数；单据上的付款条款自动生成，可手改、可恢复自动 |
| 交货地点 | 贸易术语 + 指定地点 + 具体交货地址；EXW / FCA / DAP / DPU / DDP 必填地址；切换术语时指定地点自动在装运港 / 目的港之间切换；客户库可存默认交货地址 |
| 合同条款 | 前 8–9 条由订单数据生成；其余条款可开关、修改、排序、自定义新增、从条款库插入（内置 12 条） |
| 导出格式 | 全部单据可导 PDF；发票、箱单、报关资料、报价单、PI → Excel；合同 → Word；唛头仅 PDF；导出中心可选「仅 PDF / 可编辑格式 / 两者」 |
| 交付形态 | 网页版仅为原型；正式产品用 Tauri 打包为 Windows / Mac 桌面程序，离线运行、本地存储 |
| 当前阶段 | 继续在网页原型上完善；**用户确认前不进入 M1 正式开发** |

原型地址：`prototype/index.html`
