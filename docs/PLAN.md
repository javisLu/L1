## 1. 核心理念：一次录入，全套单据

竞品的常见做法是合同、发票、箱单各填一遍，重复录入且容易三单不一致。

我们的做法：以**「订单 / 出货」**为唯一数据源——

```
            ┌─> 形式发票 PI / 销售合同 SC
订单数据 ───┼─> 商业发票 CI
（填一次）  ├─> 装箱单 PL
            ├─> 报价单 / 出货通知 / 订舱委托 / 报关资料…
            └─> 三单一致性自动校验
```

改一处，所有单据同步更新。

## 2. 单据要素清单（第一版）

### 2.1 通用 / 双方信息
- 卖方：公司中英文名、地址、电话、邮箱、网址、税号、Logo、印章/签名
- 买方：公司名、地址、联系人、电话、邮箱、税号/VAT/EORI
- 通知方 Notify Party（可选）

### 2.2 销售合同 SC / 形式发票 PI
- 合同号、日期、签约地点、有效期
- 货物明细：序号、货号、品名（中/英）、规格描述、HS 编码、图片、数量、单位、单价、金额
- 币种、贸易术语（Incoterms 2020：EXW/FCA/FOB/CFR/CIF/DAP/DDP…）+ 指定地点
- 总金额 + 英文大写（SAY US DOLLARS … ONLY）
- 溢短装（More or Less ±%）
- 包装方式、唛头 Shipping Marks
- 装运港、目的港、装运期限、分批装运 / 转运
- 付款方式：T/T（定金比例）、L/C、D/P、D/A、OA
- 保险条款、检验条款、质量/异议条款、不可抗力、仲裁/适用法律
- 受益人银行信息：户名、银行名称、银行地址、SWIFT、账号、IBAN/Routing
- 备注、双方签章

### 2.3 商业发票 CI
- 发票号、日期、合同号 / PO 号、L/C 号
- 起运地 From … To …、运输方式、船名航次 / 航班、提单号、集装箱号 / 封号
- 唛头、货描、数量、单价、金额、合计、英文大写
- 原产地、声明文字（如 "We hereby certify…"）、签章

### 2.4 装箱单 PL
- 箱号范围（C/No. 1-50）、件数、每箱数量
- 单箱净重 / 毛重、合计净重 / 毛重
- 外箱尺寸（L×W×H cm）、单箱体积、总体积 CBM
- 托盘信息（可选）、合计行、唛头

### 2.5 扩展单据（M2 起）
- 报价单 Quotation
- 出货通知 Shipping Advice
- 订舱委托书 Booking Note
- 报关资料草稿 / 报关委托书
- 原产地证申请资料

## 3. 界面：比竞品更简洁、更直观

| 设计点 | 做法 |
|---|---|
| **左填右看** | 左侧表单，右侧 A4 实时预览，所见即所得 |
| **分步向导** | ① 双方信息 → ② 货物明细 → ③ 贸易条款 → ④ 物流装箱 → ⑤ 生成单据；进度条清楚提示缺什么 |
| **像 Excel 一样填货物** | 可编辑表格，支持直接从 Excel 粘贴多行、Tab/回车切换 |
| **能算的不让人算** | 金额、合计、英文大写、箱数、CBM、毛净重自动算 |
| **能选的不让人打** | 客户库、产品库、条款库自动补全；Incoterms、付款方式下拉 + 常用条款模板 |
| **一键复制订单** | 老客户返单直接复制上一单改数量 |
| **三单校验** | 数量、金额、重量不一致时标红提示 |
| **多模板** | 多套单据样式，支持自定义 Logo、印章、配色 |
| **导出** | PDF（打印级）、Excel、Word |
| **双语** | 中文界面，英文单据（可切换中英对照） |

## 4. 「超级平台」功能路线

- **报价计算器**：采购成本 + 国内费用 + 海运费 + 汇率 + 退税 → 自动算 EXW / FOB / CIF 报价与利润
- **装柜计算器**：按箱规算 20GP / 40GP / 40HQ 能装多少箱
- **订单看板**：报价 → 确认 → 生产 → 出货 → 收款，状态一目了然
- **收款跟踪**：定金、尾款、到期提醒
- **客户 CRM**：客户档案、历史订单、跟进记录
- **HS 编码 / 退税率查询**
- **实时汇率**
- **AI 助手**：
  - 粘贴客户询盘 / PO 邮件 → 自动提取成订单
  - 品名中译英、规范化货描
  - 生成开发信、回复邮件
  - L/C 条款与单据比对，提示不符点

## 5. 技术方案

### 5.1 售卖形态（需确认）
- **A. 桌面软件买断**（闲鱼式）：数据存在本地，卖激活码
- **B. 网页版订阅 SaaS**：云端账号，按月/年收费
- **推荐：先做「本地优先」的 Web 应用**，同一套代码既能打包成 Windows / Mac 桌面软件（A），后期再接云端同步变成 SaaS（B），两条路都不堵死。

### 5.2 技术栈
| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | React + TypeScript + Vite | 生态成熟、类型安全 |
| UI | Tailwind CSS + shadcn/ui | 简洁现代、易定制 |
| 表单校验 | react-hook-form + zod | 复杂表单性能好，一套 schema 管校验 |
| 状态 | Zustand | 轻量 |
| 本地存储 | IndexedDB（Dexie） | 离线可用，容量大 |
| 单据渲染 | HTML/CSS A4 模板 → 打印 / PDF | 中文字体可靠，模板易改 |
| Excel 导出 | ExcelJS | 保留格式 |
| 桌面打包 | Tauri | 安装包小（约 10MB），跨平台 |
| 授权 | 激活码 + 机器码绑定（M3） | 防止随意分发 |
| 云端（M4） | Supabase 或自建 Node 服务 | 同步、多用户、AI 接口 |

### 5.3 核心数据模型（简化）
```
Company(我方)  Customer(客户)  Product(产品)
Order ─┬─ parties: seller / buyer / notify
       ├─ items[]: product, qty, unit, price, hs, cartonQty, nw, gw, dims
       ├─ terms: incoterm, port, payment, shipmentDate, insurance…
       ├─ logistics: vessel, blNo, containerNo…
       └─ documents: { pi, contract, ci, pl } 各自编号/日期/模板/覆盖字段
```
