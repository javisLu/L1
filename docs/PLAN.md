### 0.4 字段来源标签
每个字段标注谁来提供：S 卖方 / B 买方 / F 工厂 / FF 货代 / CB 报关行 / BANK 银行 / INS 保险 / AUTH 签发或检测机构。

### 0.5 竞品短板
1. 两套模式分开维护，需手动「同步 / 回传」，并非真正一份数据
2. 预览区拥挤：金额列、TOTAL 被截断
3. 右侧表单过窄，内容被截断（UNITED STA、LOS ANGELE）
4. 有「下一步」但没有整体进度、不知道还缺什么
5. 模板固定只能改字，自定义模板需另买版本
6. 只支持 Windows
7. 字段来源标签只是标记，不能真正让货代/工厂参与填写
8. 名称混乱（标签叫「报价单」，标题是 PROFORMA INVOICE），单据标签重叠

## 1. 核心理念：一份订单，全程贯通

```
 询盘 → 报价 → PO/PI → 合同 → 生产/验货 → 订舱/装箱 → 报关 → 提单 → 收款 → 结算
 └──────────────────── 同一份「订单」数据，一步一步往下走 ────────────────────┘
```

- 单证、报关不再是两个模式，而是订单的不同阶段，**不存在同步 / 回传**
- 竞品是「单据生成器」，我们是「订单工作台」

### 2.1 对标层：竞品所有功能 100% 覆盖（见第 0 节清单）

### 2.2 差异化层：真正实用的「超级功能」

| # | 功能 | 解决什么痛点 |
|---|---|---|
| ★1 | **智能装箱 + 装柜计算** | 输入每箱装量和箱规，自动算箱数、箱号段（C/No.1-50）、尾箱、毛净重、CBM；推荐 20GP/40GP/40HQ 柜型并显示装载率 |
| ★2 | **唛头 / 箱贴生成打印** | 正唛、侧唛自动带 PO 号、箱号、毛净重，按标签纸或 A4 排版直接打印 |
| ★3 | **AI 识别客户 PO / 询盘** | 上传客户的 PO（PDF / 图片 / Excel）或粘贴邮件，自动识别并填入订单，省掉手动录入 |
| ★4 | **提单确认件自动核对** | 上传货代发来的提单草稿，自动比对发货人、收货人、通知人、货描、件数、毛重、体积，标红差异 |
| ★5 | **信用证智能审证** | 粘贴 L/C（MT700）文本，自动解析 44C/46A/47A 等条款，生成单据要求清单、交单截止日提醒、软条款风险提示；单据货描按 L/C 原文生成 |
| ★6 | **报价计算器（多方案）** | 采购价 + 包装 + 国内费用 + 海运费 + 保险 + 汇率 + 退税 → EXW/FOB/CFR/CIF/DDP 同屏对比；按目标利润率反推报价；实时汇率 |
| ★7 | **订单看板 + 关键日期提醒** | 每单进度一眼看清；交期、截关截单、船期、L/C 效期、尾款到期自动提醒 |
| ★8 | **收款与利润结算** | 定金 / 尾款登记、银行手续费、结汇汇率，算出每单真实利润，对比报价时的预算利润 |
| ★9 | **自定义模板编辑器** | 拖拽调整单据版式、字段显隐；支持客户指定格式（上传 Excel 模板做字段映射）——竞品要另外收费 |
| ★10 | **一键发送** | 选择单据 → 合并成一个 PDF 或打包 → 自动生成英文邮件正文，复制即发 |
| ★11 | **单据版本对比** | PI v1 → v2 客户改了什么（数量、单价、交期）高亮显示，防止漏改 |
| ★12 | **HS 智能助手** | 按 HS 编码自动带出申报要素模板（品名、用途、材质、品牌、型号……）、退税率、监管条件提示 |
| ★13 | **多语言单据** | 英 / 中英对照 / 西语 / 俄语 / 法语 / 阿语，面向不同市场客户 |
| ★14 | **协作填写链接**（云端版） | 把字段来源标签变成真功能：生成链接发给货代 / 工厂 / 报关行，只能填写自己负责的字段 |

## 3. 界面设计：比竞品更简洁、更直观

### 3.1 布局
```
┌───────────────────────────────────────────────────────────────┐
│ 订单 PI-2026-001 ▾   Global Ventures  |  进度 ■■■■□□ 60%  [导出▾][发送] │
├──────────┬─────────────────────────────┬──────────────────────┤
│ 步骤条    │  表单（主区域，够宽）           │  A4 预览（可收起/放大）   │
│ ✓ 双方信息 │                              │  自动缩放适配宽度       │
│ ✓ 产品明细 │                              │  点击预览中的字段        │
│ ● 贸易条款 │                              │  → 跳到对应输入框        │
│ ○ 装箱物流 │                              │                        │
│ ○ 报关资料 │                              │  [PI][CI][PL][合同][报关] │
│ ○ 单据导出 │                              │                        │
└──────────┴─────────────────────────────┴──────────────────────┘
```

### 3.2 关键交互
| 竞品问题 | 我们的做法 |
|---|---|
| 两套导航、需回传 | 一套步骤条，报关只是其中一步 |
| 预览截断 | 预览自动缩放适配、可放大、可全屏 |
| 表单过窄 | 表单作为主区域，预览可收起 |
| 不知道还缺什么 | 步骤条显示「✓ 完成 / 缺 3 项」，点击直达缺失字段 |
| 预览和表单割裂 | **点击预览任意字段 → 直达输入框** |
| 单据清单靠自己想 | 业务场景选完 → 自动勾选所需单据，未用单据不显示 |
| 货物录入慢 | Excel 式表格，可直接粘贴多行、键盘操作 |
| 重复劳动 | 客户库、产品库、条款库自动补全；老客户返单一键复制 |

### 3.3 主要页面
1. **首页 / 订单看板**：进行中订单、待办提醒、本月出货与收款
2. **订单工作台**：步骤条 + 表单 + 预览（核心页面）
3. **产品库 / 客户库 / 条款库 / HS 记忆库**
4. **工具箱**：报价计算器、装柜计算器、唛头打印、L/C 审证、提单核对
5. **设置**：公司信息、Logo 印章、模板样式、编号规则、数据备份

## 4. 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 生态成熟、类型安全 |
| UI | Tailwind CSS + shadcn/ui | 简洁现代、易定制 |
| 表单 | react-hook-form + zod | 复杂表单性能好，校验统一 |
| 状态 | Zustand | 轻量 |
| 本地存储 | IndexedDB（Dexie） | 离线可用、容量大 |
| 单据渲染 | HTML/CSS A4 模板 → PDF | 中文字体可靠、模板可编辑 |
| Excel | ExcelJS / SheetJS | 导入导出保留格式 |
| 桌面打包 | Tauri | 安装包小，Windows + Mac |
| 授权 | 激活码 + 机器码绑定 | 对标竞品售卖方式 |
| AI（可选） | Claude API | PO 识别、审证、翻译 |
| 云端（后期） | Supabase / 自建 | 同步、协作、多账号 |

**售卖形态**：本地优先，先卖桌面买断版；同一套代码后期加云端变订阅制。

### 4.1 核心数据模型
```
Company（我方）  Customer（客户）  Product（产品）  HsMemory（HS 记忆）  ClauseLib（条款）
Order ─┬─ scenario:  transport / incoterm / payment / cargoType → requiredDocs[]
       ├─ parties:   seller / buyer / notify / consignee / factory / forwarder / broker
       ├─ numbers:   quotation / po / pi / contract / ci / oc  + 日期 + 状态
       ├─ items[]:   product, qty, unit, price, hs, origin, material, spec, photo,
       │             cartonQty, cartonSize, nw, gw, cbm, declareElements
       ├─ pricing:   discount, tax, currency, fxRate, costCalc
       ├─ terms:     payment, leadTime, shipment, insurance, clauses[], remarks
       ├─ logistics: pol, pod, vessel, blNo, containers[], marks
       ├─ customs:   tradeCountry, supervisionMode, exemption, license, sourceArea, ecommerce{}
       ├─ lc:        parsed fields, requirements[], deadlines
       ├─ payments[]: deposit / balance, date, fee, fxRate
       └─ docs:      { quotation, po, pi, contract, ci, pl, customsInvoice, customs, booking, si… }
```
